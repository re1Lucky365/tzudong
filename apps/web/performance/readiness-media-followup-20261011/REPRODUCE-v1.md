# 재현과 증거 확인

`REPORT-v1.md`가 판정 범위다. 개발 진단, production rendering, 로컬 DB와 실제 운영 시도를 구별한다. 이 패킷은 배포/SDK/실기기/field 완료 인증서가 아니다.

1. 이 PR의 소스를 checkout하고 pinned Python3.12로 `backend/bin/verify_readiness_followup_20261011.py`를 실행한다. 네트워크·인증 없이 두 complete-tree map의 detached SHA, 모든 파일 byte·source·결과와 운영 경계를 검사한다. 출력은 패킷 밖 `docs/evidence/readiness-followup-validation-v1.json`에 보존했다. frozen 기존 map은 `verify_readiness_delivery_20261011.py`로 따로 검사한다.
2. Node24.21.0/npm11.6.2와 package-lock.json 권위대로 web dependencies를 설치한다. Bun1.4.0, nativeTS7.0.2/compatTS6.0.2가 필요하다. `run_checks_v1.py`의 unit/lint/parity command 및 dirtyTrackedInputs/log SHA를 확인한다. 기본 실행은 이미 소비된 output을 덮어쓰지 않으므로 새 빈 evidence root에서 새 실행 ID로 사용한다. 전체 unit 총계는 general lane과 isolated lane의 합계다.
3. 브라우저는 Chrome154.0.8037.98, headless production이다. 390x844/820x1180/1440x900, ko-KR, mobile·touch 여부를 script에 고정했다. v6/v12/v13은 서로 다른 build이며 before/after 조건을 보존했다. build v4의 client/MY/lock SHA와 BUILD_ID를 출력에 연결했다. `build_configured_v4.mjs`는 허용 public env만 RAM에 읽고 기존 env와 tsconfig를 보존한다. 다른 host에서는 해당 public configuration을 자신의 환경으로 주입해야 한다. 운영 인증·secret을 복사하지 않는다.

Auth/REST·record-action transport는 synthetic이다. 영수증만료는 DB의 실제 보증을 별도 PG17 검사로 연결했다. 모달에서는 POST0/GET2 per-context를 확인한다. Console CSP3/미분류3을 제외하거나 health 통과로 바꾸지 않는다. 전후 독립 browser process는 각1개이며 반복 context3개를 독립 실험9개로 계산하지 않는다.
