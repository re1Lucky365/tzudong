## 이번 작은 수정: 리뷰 조회 상태

수정 전에는 첫 조회가 실패하면 기본 빈 배열을 전달했고, 보조 식당 조회의 오류를 무시해 식당을 ‘삭제된 맛집’으로 표시할 수 있었다. 실패 시 기존 데이터나 상세를 확정 정보로 조작하게 하지 않으면서, 조회 실패·로딩·실제 0건·정상 결과를 구분한다.

검증할 경계:

1. 첫 리뷰 조회 오류와 비배열 응답은 고정된 오류로 처리한다.
2. 식당 조회 실패를 삭제된 식당으로 바꾸지 않는다. 성공 응답에서 실제 누락된 식당의 기존 표시 규칙은 유지한다.
3. 실패 안내와 ‘다시 조회’를 제공하고, 재조회 중과 복구 후 상태를 구분한다.
4. 실패 시 열린 상세와 오래된 행을 숨기고, 제거되는 상세·행의 키보드 초점만 재조회 버튼으로 복구한다. 검색창으로 이동한 초점은 유지한다.
5. 합성 데이터와 외부 요청 차단으로 테스트하며 운영 장애를 주입하지 않는다.

반복 가능한 반례의 통과 여부만 보고하며, 이 표본으로 성능·사용성 개선율이나 95% 신뢰구간을 추정하지 않는다.

React Query 5.103.2는 데이터 없는 실패 쿼리를 다시 가져오는 동안 `status`를 `pending`으로 되돌려 `isError`가 거짓이 된다. 그래서 오류 표시는 `adminQueryLastReadFailed`(오류 상태이거나, 이전 오류가 있는 `pending`)로 판단한다. 이 판단이 없으면 쯔양 제보 행이 있을 때 신규 제보 재조회 중 ‘조회된 항목이 없습니다.’가 잠깐 보인다.

기존 크롤러·SQL·지식 그래프·보호 브랜치 전달 목표는 유지한다. 이 작은 결함 수정은 전체 구조의 3단계 외부 교차 검증이나 운영 자동화 완료를 대신하지 않는다.

## 일곱 번째 수정: 썸네일 준비 상태 조회 실패

`/api/admin/youtube-thumbnail-generator` 준비 상태 조회가 실패하면 알림만 뜨고 상태가 비어 있어, 채팅 상태·이미지 생성 방식·라우터 요약이 계속 ‘확인 중’이었다. 생성을 누르면 ‘잠시 후 다시 생성하세요’라고 안내했지만 다시 조회하는 경로가 없어 기다려도 풀리지 않았다. 이제 실패하면 ‘확인 실패’로 표시하고 채팅 머리글에 ‘모델 상태 다시 확인’ 버튼을 둔다. 생성 시도는 준비 상태를 다시 조회하며 그 사실을 안내한다. 재확인 중에는 버튼이 남아 초점을 유지하고, 성공하면 초점이 채팅 입력으로 옮겨진다.
